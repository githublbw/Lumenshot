# X11 性能与安装验收

2026-11-20，Ubuntu 22.04.5，AMD Ryzen 7 9800X3D，Qt 6.2.4 Release，二进制 SHA-256 前缀 `1eae3f50925c`。物理输出为一台 2560×1440 显示器。以下数据来自同机独立 Xvfb、Openbox、模拟解锁状态和白色测试桌面，包括与本机安装版相同的私有 Qt 运行库。

| 安装版采样 | 1920×1080 | 3840×2160 |
| --- | ---: | ---: |
| 后台快捷键到遮罩像素出现，30 次 P95 | 11.5 ms | 41.1 ms |
| 60 Hz 输入拖动选区，59 个可见更新间隔 P95 / 最大值 | 17.1 / 17.3 ms | 17.7 / 18.5 ms |
| 连续进入并取消选区，第 1 / 10 / 20 / 30 次 RSS（MiB） | 35.8 / 51.6 / 51.6 / 51.6 | 35.7 / 99.0 / 99.0 / 99.0 |

安装版在 1080p 初次后台启动后，空闲 60 秒 CPU 为 0.000%（进程计时精度内），平均和最大 RSS 均为 32.7 MiB。完整开发插件环境同条件为 98.1 MiB，超出 80 MiB 目标；图形库 LLVM 在一次开发环境采样中占 42.1 MiB。4K 使用后内存稳定在约 99 MiB，亦高于初始空闲目标。当前仍需目标机长期使用数据。

优化前，完整开发插件环境的 1080p 唤起 P95 为 333.1 ms；相同环境优化后为 11.2 ms。修改仅跳过本来就隐藏的工作台与浮窗的淡出等待。测试从发送模拟按键前开始，在虚拟屏幕首次检测到遮罩像素时结束。拖动用新露出的选区像素计时。部分取消操作时 Qt 输出 BadWindow/TranslateCoords 警告，采样完成。以上结果没有覆盖 GNOME 合成器、显示器输出和真实鼠标的端到端延迟。

4K 桌面回归通过，包括大面积模糊、马赛克和 PNG 保存后的逐像素比较。PNG 已改为后台编码并原子提交。未测保存过程的取消延迟、箭头连续拖动和遮挡调整的帧间隔。负坐标、分数缩放、边缘裁剪已通过合成图测试；真实双屏跨屏裁剪、混合缩放及热插拔待有设备后验收。当前区域截图限定工作台所在显示器。

在含空格的临时用户目录中，实际安装旧二进制、更新为新二进制、运行命令入口、验证桌面入口格式并卸载。卸载后程序和自启入口已清除，测试图片逐字节一致，偏好配置保留。安装步骤见[使用与卸载](../packaging/使用与卸载.md)。

复测使用 `PERF_CHECK=1 MEASURE_IDLE=1 TEST_SCREEN=1920x1080 bash tests/check-panel-x11.sh /绝对路径/lumenshot`，将分辨率改成 `3840x2160` 可重复高负载采样。去掉两个测量开关可运行界面回归。安装生命周期测试为 `bash tests/check-install.sh 旧二进制 新二进制`。Wayland、真机登录重启及物理多屏发布验收仍未完成。
