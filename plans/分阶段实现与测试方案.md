# Lumenshot：分阶段实现与测试方案

> 状态：阶段 0 为 60%（3/5）。X11 点击工作台的区域截图、整屏、复制、保存已获得当前机器的用户试用反馈。本批新增完整可见窗口截图、同会话重复启动唤回和置顶预览。Release 构建、11 个裁剪场景和隔离 X11 界面测试通过；Wayland、多屏混合缩放、完整标注、后台与发布验收待进行。

## 1. 目标与当前环境

**主流程：** 登录桌面后后台常驻 → 按快捷键 → 拖拽选区 → 点击选区旁的中文工具栏做标注 → 复制、保存或置顶。打开编辑器和完成截图均不依赖网络。首版含区域、全屏和窗口截图；窗口截图指选定窗口，另验证是否支持一键截取当前窗口。

| 项目 | 当前实测或确认的事实 |
| --- | --- |
| 项目 | 当前只有 `plans/`，没有应用源码或现成技术栈 |
| 优先适配 | Ubuntu 22.04.5 LTS，GNOME 42.9，当前以 X11 登录 |
| 桌面门户 | `xdg-desktop-portal` 1.14.4；当前会话可查询 `Screenshot` 版本 2，未查询到 `GlobalShortcuts` 接口。接口存在不等于截图、授权或窗口模式已经实测可用 |
| 启动环境 | 当前 `graphical-session.target` 活跃；尚未运行 Lumenshot，也未验证登录启动或退出行为 |
| 开发组件 | 系统软件源有 Qt 6.2.4 和对应的 Wayland 插件，当前未安装；尚未切换到 Wayland 验证 |

**首版发布条件：** 同一版本在 Ubuntu 22.04 的 GNOME X11 和 GNOME Wayland 都完成真机验收。支持系统操作的降级方式，但必须在中文界面写清楚；不能把只在 X11 成功的功能当成 Wayland 已支持。KDE、其他发行版和桌面版本不列入首版兼容承诺。

## 2. 技术路线与界面设计

**推荐 C++17 + Qt 6.2 Widgets + CMake**，使用原生桌面窗口，而不是内嵌浏览器。Qt 负责界面、绘制、剪贴板和测试；X11 后端单独处理屏幕抓取与全局键，Wayland 后端通过桌面门户请求用户授权截图。若部分能力只能在较新 Qt 上实现，先找与 Ubuntu 22.04 兼容的替代，不默认要求升级系统。

| 功能 | X11 路径 | GNOME Wayland 路径 |
| --- | --- | --- |
| 区域／全屏 | 先抓取桌面，再打开选区界面；不把自己的遮罩和工具栏截进去 | 优先在门户允许的范围内拿到全屏图后做应用内裁剪；若桌面只允许系统选区，就由系统完成选区，再进入相同的中文编辑器。取消授权不打开编辑器、不留图 |
| 窗口 | 优先获取快捷键触发时的活动窗口；验证窗口边框、遮挡、窗口消失等情况，不能准确截取时明确提示 | 探测系统截图界面是否支持用户选择窗口；不存在可用接口时，不承诺一键截当前窗口，明确区分系统窗口选择与手动框选 |
| 全局快捷键 | 应用尝试注册 `Ctrl+Alt+A`，检测冲突并提示改键；不占用系统已有映射 | 若运行时有 `GlobalShortcuts` 门户，按系统授权配置；否则在 GNOME「键盘 → 自定义快捷键」中将按键绑定到 `lumenshot --capture region`。不静默修改系统快捷键 |
| 置顶 | 通过窗口管理器支持的方式请求“总在最前” | 应用先尝试置顶；若合成器忽略请求，保留系统标题栏并验证 GNOME 窗口菜单的「总在最前」。如果系统也不能实现，明确告知，不能把普通浮窗标为已置顶 |
| 后台和自启 | 两种会话共用普通用户权限和单实例机制。默认采用 XDG 桌面自启动，在登录图形桌面后启动；不在登录前或锁屏时截屏，也不需要管理员权限 | 与 X11 相同 |

若桌面门户无法把系统所选图片交给应用，或 Wayland 实测没有可用置顶方式，先修正兼容路线，再决定范围；不能以普通浮窗或外部截图后手动导入代替首版必需能力却仍称完整支持。

### 中文功能区

| 场景 | 设计 |
| --- | --- |
| 截图选区 | 拖拽时可取消、调整边缘和查看像素尺寸；选中后，工具栏优先贴下边，空间不足翻到上边并限制在当前屏幕内；再不足时分两行，避免挡住选区手柄 |
| 标注工具栏 | 图标按「遮挡／标注」「撤销／重做」「复制／保存／置顶／关闭」分组；包含矩形遮挡、椭圆遮挡（可画正圆）、模糊、马赛克、箭头、文字。只在选中相关工具后显示颜色、线宽、字号或处理强度；悬停显示简短中文名称，键盘聚焦时也提供中文名称 |
| 置顶窗口 | 可拖动、缩放、关闭，悬停或键盘聚焦时显示复制、保存、取消置顶和关闭；浮动按钮不写入导出图片。Wayland 需要系统操作时提供中文指引，保留对应系统窗口操作入口 |
| 托盘与设置 | 托盘放区域／全屏／窗口截图、设置和退出；没有托盘支持时，仍能通过应用菜单启动设置或发起截图。设置只放常用项：快捷键、自启动、保存目录和能力状态 |

**隐私规则：** 默认不自动保存、不建截图历史、不上传；日志不记录图片像素、标注文字或剪贴板内容。矩形／椭圆遮挡默认完全不透明，输出把标注和原图合成一张图，复制、保存和置顶使用同一合成结果。模糊与马赛克仅是视觉弱化，不作为可靠的敏感信息遮挡。门户交回的图片在应用读入后不再复制到历史或缓存；只删除应用拥有并能安全清理的临时文件，不删除用户文件。若系统生成并保留文件，应按实测说明其行为。

## 3. 实施阶段与验收

### 阶段 0：两种会话的能力验证

- 建最小测试程序，只跑 X11 抓取和快捷键、Wayland 门户截图及取消、系统快捷键调用、窗口置顶请求和中文系统指引。记录 GNOME 能否选窗口、门户返回的图像范围、是否需要每次确认、置顶和失去焦点后的表现。
- 在当前 X11 与同机 GNOME Wayland 分别验证；如果当前机器不能进入 Wayland，先把它标为未验收，再安排可运行 Wayland 的测试环境。虚拟机可用于早期验证，不替代发布前的真机流畅度测试。
- **通过条件：** 实测两种会话都能从快捷键发起截图并把图交给应用；Wayland 的区域选择和置顶必须有可走通的路径，明确哪些功能需要系统操作。系统不提供窗口选择时，保留区域截图，但将窗口模式缺口列为发布范围决策，不默默跳过。

### 阶段 1：基本截图闭环

- 实现单实例、中文应用入口、选区交互和共用图像坐标转换。接通两种后端的区域、全屏和窗口模式；支持复制到剪贴板和手动保存 PNG。未支持的一键截窗口操作按阶段 0 实测结果处理。
- **自动验证：** 用已知颜色的测试图检查裁剪结果；覆盖反向拖拽、零面积、超出屏幕、负坐标、不同缩放比；检查保存失败、同名文件确认、门户取消或失败后的状态恢复。用模拟门户验证异步结果，不把模拟当成真机验证。
- **桌面验收：** 分别用鼠标和快捷键完成截图；检查截图中没有工具栏、遮罩或前一张选区。粘贴到另一个应用并打开保存文件，核对像素和尺寸；连续触发、取消后能再次开始。剪贴板至少保证后台进程运行期间可粘贴，退出后是否保留单独记录。

### 阶段 2：中文工具栏、标注和置顶

- 实现工具栏和悬停中文名称；加入矩形／椭圆遮挡、模糊、马赛克、箭头、文字、撤销与重做。置顶窗口使用已编辑的图像，并按会话能力决定交互。
- **自动验证：** 用合成图检查遮挡范围内像素完全不透明；检测模糊／马赛克只修改选中的范围；核对导出与剪贴板像素一致，撤销／重做能恢复图像，撤销后新编辑清空重做。验证画布外绘制和取消文字编辑不会改坏图像。
- **桌面验收：** 在显示器边缘和小选区操作工具栏，检查无越界、无重叠；逐个悬停核对中文名称，用中文输入法输入文字并导出。置顶后切换到两个普通窗口，实际核对图片仍置顶，并能拖动、缩放和取消。系统授权界面的语言由桌面环境决定。

### 阶段 3：后台、自启与流畅度

- 接入桌面自启动、托盘与设置。桌面自启动、应用菜单和快捷键命令均进入同一实例；快捷键命令只向当前用户、当前图形会话派发一次截图请求。使用事件触发，不靠定时轮询；捕获后重用静态底图，拖动只重绘变化区域，保存编码和大面积模糊／马赛克避免阻塞界面，撤销保留编辑步骤而不是每步复制完整屏幕。
- **桌面验收：** 两种会话中分别启用自启、注销重登，检查不打开主窗口且只有一个进程；禁用后重登确认不启动。验证重复启动、快捷键冲突、无托盘、锁屏后解锁、休眠后恢复、桌面菜单退出，以及剪贴板与保存行为。至少在目标机重启一次验证登录自启。若目录只读或快捷键无法注册，显示可执行的中文提示，应用保持可用。
- **性能验收：** 按下表记录版本、硬件、会话类型、屏幕分辨率及缩放，记录应用等待时间和系统确认等待时间。逐项记录实测值、是否通过及复现条件。

### 阶段 4：发布与后续增强

- 准备面向 Ubuntu 22.04 的安装包或用户级安装方案，以及中文使用与排错说明。说明如何启停、自启、配置 Wayland 快捷键、识别不支持的能力和卸载。先验证安装、升级、卸载，确认卸载不会留下仍会启动的配置，也不会删除用户截图。
- **发布检查：** 运行下节的构建和验收矩阵。关键路径、遮挡不透明、会话隔离和自启去重未通过时不发布；兼容缺项和性能未达标处要如实记录。后续优先做延时截图、重复上次选区和多图置顶；截图历史必须可关闭，识字、录屏、上传与分享不进入首版。

## 4. 性能与发布验收清单

以下是首版目标值，交付时用实测报告确认，不用理论推算代替。按 Ubuntu 22.04 目标机、发布构建、无其他重任务测量；在单屏 1080p 与至少一种高负载显示配置上测试，结果分开记录。

| 项目 | 测法与通过标准 |
| --- | --- |
| 唤起反馈 | 后台已就绪，单屏 1080p 每种会话重复 30 次，记录第 95 百分位（95% 的试次不超过此值）。X11 从按键到首帧选区 ≤ 250 毫秒；Wayland 从用户确认系统截图到编辑器首帧 ≤ 400 毫秒，另外记录按键到系统提示出现的时间，不把等待用户确认算入应用延迟 |
| 拖拽与标注 | 逐个会话连续拖动选区、画箭头和调整遮挡，结合输入与重绘计时及录屏复核。60 Hz 下，有持续输入的区间第 95 百分位重绘间隔 ≤ 33 毫秒，不出现超过 100 毫秒的应用侧停顿。仅统计拖动期间，不统计待机不重绘的时间 |
| 保存与持续使用 | 用 4K 测试图执行较大区域的模糊、马赛克及 PNG 保存，期间窗口仍可拖动或响应取消。连续执行 30 次截图并关闭窗口后，确认没有逐轮增长的内存、重复进程或应用遗留的临时图片 |
| 空闲资源 | 无编辑器和置顶窗口时采样 60 秒：应用进程平均 CPU 占用 < 1%（按单核计），常驻内存（RSS）目标 ≤ 80 MiB。较高时先检查轮询、残留画布和编辑历史，再复测 |

| 测试环境 | 必测场景 |
| --- | --- |
| Ubuntu 22.04 / GNOME X11 | 快捷键冲突、区域／全屏／窗口、工具栏、复制保存、置顶、自启和性能 |
| Ubuntu 22.04 / GNOME Wayland | 系统按键绑定、允许／拒绝／取消系统截图、区域／全屏／窗口能力、置顶或系统操作路径、自启和性能 |
| 两种会话的高负载显示配置 | 优先双屏，包含副屏在左侧产生的负坐标，以及系统实际提供的混合缩放；检查边缘选区、跨屏选区、像素输出、工具栏位置和拔插后是否恢复。跨屏行为如果只能由系统选择器提供，则按会话记录限制；没有合适硬件就标为未验证 |

安装构建工具与 Qt 6 开发包后，可在项目根目录构建并运行已有的裁剪测试：

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON
cmake --build build --parallel
ctest --test-dir build --output-on-failure --no-tests=error
```
